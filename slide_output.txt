=== SLIDE 17 ===
  Requirements — Non-Functional
  17
  The system should reach component F1 ≥ 0.80, calorie error ≤ 18 % and calibration error ≤ 0.10.
  Results should arrive within 20 seconds at no more than $0.01 per meal.
  Every displayed nutrient must trace back to a database record.
  Offline mock mode must give repeatable results without internet.
  Runs on a CPU-only laptop with 8 GB RAM; photos stay stored locally.
  A non-medical disclaimer is shown on every result.

=== SLIDE 18 ===
  Requirements — Technology Stack
  18
  The system is written in Python with Pydantic v2 data schemas.
  Gemini 2.5 Flash is used as the vision-language model for perception only.
  SQLite (WAL mode) stores records and Chroma stores vectors.
  Retrieval uses bge-small-en-v1.5 embeddings, BM25, rank fusion and a cross-encoder reranker.
  Isotonic regression calibrates the fused confidence signals.
  The user interface is a Streamlit web app.
  It runs on a standard Windows laptop, CPU-only, with 8 GB RAM.

=== SLIDE 19 ===
  Dataset
  19
  Our own gold_v1 set has 150 images of 60 weighed Indian meals.
  IFCT 2017 gives 528 Indian foods with about 150 nutrients each.
  USDA FoodData Central adds about 8,000 foods as a global fallback.
  The Indian Thali Dataset has 7,900 multi-dish images for segmentation.
  The Weight Dataset has 1,400 images with measured component mass.
  Data is split 60 / 20 / 20 by meal, never by image.

=== SLIDE 22 ===
  Conclusion
  22
  Calorie error is split into identity, mass, grounding and calibration, and each is solved separately.
  The vision model never predicts numbers; all nutrients come from verified tables.
  Calibrated confidence and selective questions make the output honest.
  The system is built for mixed Indian platters.
  Phase 1 is done and the pipeline skeleton is under way.
  Future work includes 3D volume from video and more regional recipes.
